# Linked List CRT Reskin -- Setup Guide
# Covers: PC Password Panel + Linked List Puzzle Panel

Prereq: complete Parts 1-2 of CRT_SETUP_GUIDE.md first (draw the three bezel PNGs and
create the CRTScanlineOverlay material). This guide assumes those assets already exist at:
  Assets/Sprites/UI/Bezel/crt_bezel_h.png
  Assets/Sprites/UI/Bezel/crt_bezel_bottom.png
  Assets/Sprites/UI/Bezel/crt_bezel_v.png
  (Material) CRTScanlineOverlay using Custom/UI/CRTScanlineVignette shader

---

## PANEL A -- PC Password Panel (PasswordScreenUI)

This is the first thing the player sees when interacting with the computer prop.
Theme: old ARBITEX security login terminal.

### Step 1 -- Panel header

Add a TMP_Text child at the very top of the panel content area.
  Text: ARBITEX SECURITY TERMINAL v0.67
  Font size: 14, Bold
  Alignment: Centre
  Color: #00FF41
  Enable Underlay on the font material (see Part 4 of CRT_SETUP_GUIDE.md for glow settings)

### Step 2 -- Hierarchy setup

Restructure (or confirm) the PC Password Panel children in this order:

  [PC Password Panel]     <-- add CanvasGroup + PuzzleCRTController here
    [BG]                  <-- Image, color #050D05 (near-black, slight green tint)
    [Content]             <-- wrapper holding all existing UI children
      [Header]            <-- TMP_Text "ARBITEX SECURITY TERMINAL v0.67"
      [StatusText]        <-- existing status TMP_Text
      [PasswordInputField]<-- existing TMP_InputField
      [LoginButton]       <-- existing button
      [CloseButton]       <-- existing close/X button
    [CRTOverlay]          <-- NEW full-panel Image with CRTScanlineOverlay material
    [Bezel_Top]           <-- NEW
    [Bezel_Bottom]        <-- NEW
    [Bezel_Left]          <-- NEW
    [Bezel_Right]         <-- NEW

Unity UI renders children bottom-up in the list, so BG must be first and bezels last.
CRTOverlay goes above Content so scanlines layer over the text.

### Step 3 -- BG Image

  GameObject name: BG
  Component: Image
  Color: R:0.02 G:0.05 B:0.02 A:1  (hex #050D05)
  RectTransform: stretch-fill (AnchorMin 0,0 -- AnchorMax 1,1 -- all offsets 0)
  Raycast Target: OFF

### Step 4 -- Content wrapper

  RectTransform: stretch-fill with padding
  Left: 56   Right: 56   Top: 56   Bottom: 56
  (this keeps content clear of the bezel strips)
  No Layout Group needed here -- children are manually positioned

### Step 5 -- Status and Input colors

  StatusText TMP_Text:
    Default color set in code (PasswordScreenUI.cs) -- no Inspector override needed
    Font size: 13
    Enable Underlay glow: Color #00FF00 at 80% alpha, Dilate 0.3, Softness 0.4

  PasswordInputField:
    Target Graphic color: #0D190D  (dark green bg for the caret area)
    Text Component color: #33FF33
    Placeholder color: #1A661A at ~60% alpha
    Caret color: #33FF33

  LoginButton:
    Normal color: #0D190D
    Highlighted color: #1A3D1A
    Pressed color: #000D00
    Text label color: #33FF33
    Font size: 13, Bold

  CloseButton (X):
    Same color states as LoginButton
    Text label: X  (ASCII -- do not use Unicode close symbol)

### Step 6 -- CRTOverlay

  GameObject name: CRTOverlay
  Component: Image
  Material: CRTScanlineOverlay
  Source Image: None (leave blank)
  Color: white RGBA(1,1,1,1)
  RectTransform: stretch-fill (all offsets 0)
  Raycast Target: OFF  -- critical, otherwise it blocks all input

### Step 7 -- Bezel strips (same settings as Quiz panel)

Import sprites with: Texture Type = Sprite (2D and UI), Filter Mode = Point, Compression = None

  Bezel_Top:
    Source Image: crt_bezel_h.png
    Anchor: top-stretch (Min X=0 Max X=1 Min Y=1 Max Y=1)
    Height: 56  |  Pivot Y: 1  |  Offsets Top/Left/Right: 0

  Bezel_Bottom:
    Source Image: crt_bezel_bottom.png
    Anchor: bottom-stretch
    Height: 56  |  Pivot Y: 0

  Bezel_Left:
    Source Image: crt_bezel_v.png
    Anchor: left-stretch
    Width: 56
    Top offset: 56  Bottom offset: 56  (avoids overlap with horizontal strips at corners)

  Bezel_Right:
    Source Image: crt_bezel_v.png
    Anchor: right-stretch
    Width: 56
    Top offset: 56  Bottom offset: 56
    Scale X: -1  (mirror the left strip)

### Step 8 -- PuzzleCRTController

  Add PuzzleCRTController to the PC Password Panel root.
  Unity adds a CanvasGroup automatically if missing.
  Default settings are fine (flicker ~0.1, interval ~4s).
  If flicker feels too harsh, lower Flicker Depth toward 0.05.

## PANEL B -- Linked List Puzzle Panel (LinkedListPuzzleUI)

This panel is the ARBITEX memory management console. The game world was bleeding through
because there was no opaque background -- the BG Image below fixes that as a side effect.

### Step 1 -- Panel header text

The panel already has an ARBITEX header string generated by LinkedListPuzzleUI.cs.
Select that TMP_Text and apply:
  Color: #00FF41
  Font size: 14, Bold
  Alignment: Centre
  Enable Underlay glow: same settings as Password panel header above

### Step 2 -- Hierarchy setup

  [Linked List Puzzle Panel]  <-- add CanvasGroup + PuzzleCRTController here
    [BG]                      <-- Image, color #050D05, stretch-fill, Raycast OFF
    [nodeContainer]           <-- existing scatter zone (pivot MUST stay at 0.5,0.5 -- no Layout Group)
    [HeadSide]                <-- existing HEAD pointer area
    [NullSide]                <-- existing NULL_PTR terminal area
    [CRTOverlay]              <-- NEW full-panel Image, CRTScanlineOverlay mat, Raycast OFF
    [Bezel_Top / Bottom / Left / Right]  <-- NEW, same settings as Panel A Step 7

BG must be first child. CRTOverlay and bezels must be above nodeContainer/HeadSide/NullSide
in the hierarchy so scanlines and bezels render on top.

IMPORTANT: nodeContainer pivot stays (0.5, 0.5) with NO Layout Group. LLArrow positioning
depends on this. Do not add a VerticalLayoutGroup or HorizontalLayoutGroup to it.

### Step 3 -- LLNodeBlock prefab reskin

Open the LLNodeBlock prefab and change:
  Root Image (background):
    Color: #0D190D  (dark phosphor green bg)
    Preserve sprite if you have one, just tint it dark

  Value TMP_Text:
    Color: #33FF33
    Font size: 16, Bold
    Enable Underlay glow

  Address TMP_Text (if present):
    Color: #1A661A  (dim green for secondary info)
    Font size: 10

  LLNextHandle child ("[-?]" or "[->]" port button):
    Normal color: #0D190D
    Selected/Highlighted color: #D98C00  (amber -- indicates selected/pending state)
    Port label TMP_Text color: #33FF33

  SetCorrupted() already flashes the node red -- verify the corruptedColor field in
  LLNodeBlock inspector is set to #BF2000

### Step 4 -- LLHeadPointer prefab reskin

  Background Image: Color #0D190D
  "HEAD" label TMP_Text: Color #00FF41, Bold
  Port button (if present): same amber highlight as LLNextHandle above

  NOTE: HEAD was previously grey/white. This fix makes it match the node theme.

### Step 5 -- NULL_PTR terminal (LLNullTerminal) reskin

The NULL_PTR terminal needs a visible bordered box. Do this with nested Images:

  [LLNullTerminal root]
    [Border]    <-- Image, color #33FF33, stretch-fill (this is the visible border)
    [Fill]      <-- Image, color #0D190D, stretch-fill with 2px inset on all sides
                    (AnchorMin 0,0 AnchorMax 1,1, Left/Right/Top/Bottom offsets all = 2)
    [NullText]  <-- TMP_Text "NULL_PTR", color #33FF33, centre-aligned, size 13

  This gives a 2px phosphor-green border around the dark fill -- no extra sprites needed.

### Step 6 -- Arrow color

LLArrow.cs already forces arrow color to #33D959 in Awake().
Verify in the ArrowPrefab Inspector that:
  Shaft Image: no sprite set on the root Image (sprite = None)
  ArrowHead child: width ~20, height ~15  (was 100x100 -- shrink if not already done)
  Raycast Target on root Image: OFF

If the shaft still shows yellow, manually set Color on the shaft Image to #33D959 in Inspector.

### Step 7 -- CRTOverlay + Bezels

Same as Panel A Steps 6-7. Exact same settings apply.

### Step 8 -- PuzzleCRTController

Add PuzzleCRTController to the Linked List Puzzle Panel root.
Same default settings as Panel A.

## Known Gotchas

1. CRTOverlay Raycast Target MUST be OFF -- if it is ON, it silently blocks all mouse
   clicks on the node ports and input fields below it.

2. nodeContainer pivot must stay at (0.5, 0.5) with no Layout Group. Arrow world-space
   calculations in LLArrow.cs break if pivot shifts or a layout component forces
   position recalculation.

3. PuzzleCRTController uses WaitForSecondsRealtime internally (timeScale = 0 while
   puzzle is open). Do not swap to WaitForSeconds -- the flicker will freeze.

4. Bezel_Right uses Scale X = -1 to mirror the left sprite. Make sure this is set on
   the RectTransform scale, not a custom component, otherwise layout calculations
   stay correct.

5. Do not put a CanvasGroup on the BG, Content, or nodeContainer children. Only the
   panel ROOT should have the CanvasGroup (PuzzleCRTController needs it there).

6. LLNodeBlock prefab changes apply to ALL instances in the scene automatically.
   If you have any overrides set per-instance, clear them after prefab edits.

7. The ArrowPrefab root Image must have Source Image = None. If a sprite is assigned
   it stretches across the full arrow length instead of just the arrowhead.

8. NULL_PTR border trick uses two nested Images. The outer (Border) must be strictly
   BEHIND the inner (Fill) in the hierarchy -- Unity renders children front to back
   in the list, so Border first, Fill second, NullText third.
